# مراجعة المصدر وربط الشاشات — 15 أكتوبر 2026

## النطاق الذي تمت مراجعته

- مشروع البناء الفعلي: `AlSaqr.Accounting.csproj`، تطبيق Windows Forms على .NET 8.
- نقطة الدخول: `Program.cs`.
- الشاشة الرئيسية الفعلية: `MainForm.cs` (في مساحة الأسماء `AlSaqr.Accounting`).
- شاشات الفواتير والمردود والكاشير: `Forms/LegacyInvoiceEntryForm.cs` و`ReturnEntryForm.cs` و`Forms/CashierForm.cs`.
- خدمات الحسابات: `Services/AccountingService.cs` و`Services/ReturnService.cs` و`Services/CashierService.cs`.
- جرد الشاشة الأصلية ومراجع التشغيل: `الشاشات_ومراجع_التشغيل.csv` و`00_REAL_INTERNAL_UI_DESIGN.txt` و`GTSErp_SOURCE_MAP.txt`.

## النتائج المؤكدة

1. يبدأ التطبيق الحالي عبر `Program.cs` ثم تسجيل الدخول، وبعدها `MainForm(AuthUser)`. تُنشأ قوائم التنقل من دوال فعلية مثل `ShowAccounts` و`ShowJournals` و`ShowProducts` و`ShowInvoices` و`ShowReturns` و`OpenCashier` و`ShowReports`.
2. أسماء بعض عناصر صورة لوحة التشغيل القديمة تتوافق مع نماذج قديمة، منها `FrmReceiptsScaffolds` و`FrmCashirWithOutGroup` و`FrmOrderReturn` و`FrmPurchasesReturnNoPurchCode`. هذه الأسماء موجودة في فهارس وتقارير المصدر القديم، وليست نماذج تشغيل ضمن مشروع Windows Forms المصغّر الذي يُبنى حاليًا.
3. ملف `AlSaqr.Accounting.csproj` يستبعد بعض النماذج المكررة/القديمة عمدًا. لذا لا يصح ربط بطاقة تحمل اسم نموذج قديم إلى شاشة حديثة لمجرد تشابه الاسم، ولا يصح الادعاء بأن كل الشاشات القديمة أعيد تنفيذها.
4. في شاشة إدخال الفاتورة الحالية `Forms/LegacyInvoiceEntryForm.cs`، أزرار البحث والطباعة والتنقل بين أول/سابق/التالي/آخر مستند غير موصولة، وشريط الأيقونات الجانبي معطل. عمليات اعتماد الفاتورة نفسها موصولة بخدمة المحاسبة المحلية.
5. أداة اتصال SQL Server الحالية في `Forms/LocalSqlServerConnectionForm.cs` تختبر الاتصال وتقرأ مخطط قاعدة البيانات وتعرض معاينة قراءة فقط؛ العمليات المحاسبية ما زالت تعمل على SQLite المحلية وفق `README.md`. هذا ليس تكامل كتابة مع قاعدة `GtsDb2026`.
6. جرد التشغيل القديم `الشاشات_ومراجع_التشغيل.csv` يبيّن أن بعض نماذج المصدر القديم لديها أحداث ومراجع فتح، وبعضها يحتاج مراجعة. لا تكفي هذه الإشارات وحدها لإثبات أن كل حدث يصل إلى معالج سليم أو أن النموذج يبني بنجاح.
7. سجل المصدر القديم `DamagedFileReport_14480430_101918.txt` يذكر أخطاء ترجمة كثيرة في نماذج قديمة، ومن ضمنها نماذج الكاشير والمردودات المذكورة أعلاه. يجب إصلاحها وفحصها داخل المصدر الأصلي قبل إعادة إدخالها في مشروع الإصدار.

## إصلاحات هذا الفرع

- قصر خيارات إعداد اتصال SQL Server، إعدادات المنشأة والثيم، إدارة المستخدمين والنسخ الاحتياطي على مدير النظام، مع فحص صلاحية داخل نقاط فتح اتصال SQL Server وتنفيذ النسخ الاحتياطي.
- إضافة معاينة طباعة إلى جداول السجلات التي تستخدم `ShowTablePage` وإلى مركز التقارير، باستخدام `ReportPrintService.Preview` بدل ترك طباعة السجلات وظيفة يتيمة.
- لا يغيّر هذا الفرع وجهة تخزين العمليات المحاسبية، ولا يكتب في قاعدة SQL Server القديمة، ولا يدّعي أن النماذج القديمة المعطوبة أصبحت قابلة للبناء.

## الخطوات التالية المطلوبة لإكمال الربط القديم

1. توفير شجرة المصدر الأصلي القابلة للبناء مع ملفات `.cs` و`.Designer.cs` و`.resx` وملف المشروع والاعتماديات المتوافقة، وليس تقارير الجرد وحدها.
2. توليد سجل لكل بطاقة/قائمة قديمة يحتوي على اسم النموذج، دالة الفتح، معالج الحدث، الصلاحيات، والخدمات/الجداول المستخدمة.
3. تصنيف كل شاشة: مدعومة حاليًا، مفقودة، بديلة حديثة، أو متوقفة عمدًا. لا تُوصل الشاشة المفقودة إلى شاشة غير مكافئة محاسبيًا.
4. اختبار بناء Windows، وصلاحيات الأدوار الثلاثة، والتنقل، والطباعة، والباركود، والمردودات، وتوازن القيود وحركة المخزون على قاعدة اختبار.
5. لا يُحوّل التخزين إلى `GtsDb2026` إلا بعد مطابقة المخطط والمفاتيح ومعاني الحالات والأرصدة واختبار القراءة والكتابة على نسخة معزولة.
