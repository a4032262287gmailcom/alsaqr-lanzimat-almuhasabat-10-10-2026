# بوابة الإطلاق التجاري — الصقر لأنظمة المحاسبة

**الإصدار المستهدف:** Windows x64  
**تاريخ المراجعة:** 14 أكتوبر 2026  
**حالة الإطلاق:** **معلّق — لا يُسوّق حاليًا كحل فوترة ضريبية متوافق أو كبديل موصول بقاعدة النظام القديم.**

هذا سجل قرار إطلاق، وليس إعلانًا تسويقيًا. لا يتحول البند إلى «مكتمل» إلا بدليل يمكن مراجعته: نتيجة CI، سجل اختبار قبول، ملف تسليم، أو مستند قانوني صحيح.

## 1. ما تحقق آليًا

- [x] نجح بناء تطبيق Windows x64 واختبارات المحاسبة الآلية على الالتزام 4d4f3d579fe377ffc851c907b3be33bdeeb3352b.
- [x] نجح بناء أداة إصدار الترخيص واختبار رفض مفتاح توقيع غير مطابق في سير العمل نفسه.
- [x] توثيق هوية المنتج باسم «الصقر لأنظمة المحاسبة» مع عدم الادعاء بأن العلامة مسجلة.
- [x] وجود نسخ احتياطي SQLite وإعدادات طباعة وطباعة إيصال حراري في شاشة الكاشير وفق حدود التنفيذ الموثقة.

**ملاحظة:** نجاح Smoke Tests لا يساوي اختبار قبول كاملًا على جهاز Windows وطابعة وقارئ باركود فعلي، ولا يثبت الامتثال القانوني أو صحة جميع المعالجات المحاسبية.

## 3. تحديد المنتج الذي يمكن بيعه

هذه النسخة **تطبيق مكتبي محلي** يعمل على Windows وتُخزّن قاعدة بياناته الأساسية في:

%LOCALAPPDATA%/AlSaqrAccounting/accounting.db

لا تفترض أن تثبيت البرنامج على عدة أجهزة يجعلها تشترك في قاعدة واحدة أو يسمح بالتزامن بين الفروع. إعداد SQL Server الموجود حاليًا لفحص الاتصال والمخطط فقط. يجب تحديد هذا النطاق كتابةً في العرض التجاري وألا يُوعد العميل بتعدد الفروع أو المزامنة أو التشغيل السحابي قبل تنفيذها واختبارها.

## 4. خطوات الإطلاق بالترتيب

1. [ ] حسم نطاق المنتج: مستقل محليًا أم تكامل مع قاعدة العميل القديمة، وعدد الأجهزة والمستخدمين والفروع.
2. [ ] حسم نطاق الفوترة: لا يعلن امتثال ZATCA قبل تحقيق المتطلبات المنطبقة ووجود نتائج اختبار موثقة.
3. [ ] إكمال اختبارات القبول اليدوية، بما فيها الباركود والطابعة الحرارية والضريبة والمردودات والنسخ والاستعادة.
4. [ ] التحقق من مفتاح الترخيص الخاص وإصدار رخصة اختبار صالحة؛ لا يبدأ تحصيل تراخيص مدفوعة قبل إثبات القدرة على إصدارها.
5. [ ] إعداد بيانات الناشر القانونية والعقد وسياسة الدعم والخصوصية والسعر والفاتورة التجارية.
6. [ ] بناء حزمة الإصدار من Release AlSaqr Accounting for Windows والتحقق من المثبت والملف المضغوط ونتائج الاختبارات.
7. [ ] توقيع الحزم رقميًا عند توفر الشهادة، وإنشاء سجل إصدار يتضمن رقم النسخة وبصمات SHA-256.
8. [ ] توقيع قبول النسخة المحددة قبل تسليمها لأول عميل، وحفظ نسخة من ملف التثبيت ونتيجة الاختبار.

## 5. قاعدة قرار البيع

**لا تُسلّم النسخة كبرنامج فوترة ضريبية متوافق أو كبرنامج متصل بقاعدة GtsDb2026 قبل إغلاق بواباتها أعلاه.** أي تجربة خارج هذا النطاق يجب أن تكون محددة كتابيًا، وألا تُستخدم لإصدار مستندات ضريبية إلا بعد تحقق الامتثال المطلوب للعميل.
