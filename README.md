# الصقر — النظام المحاسبي المكتبي

تطبيق محاسبي مستقل لنظام Windows مبني باستخدام C# وWindows Forms و.NET 8، مع قاعدة بيانات محلية دائمة باستخدام SQLite.

## الوحدات المتاحة

- **تسجيل الدخول والصلاحيات:** إنشاء مدير النظام عند التشغيل الأول، كلمات المرور مجزّأة باستخدام PBKDF2-SHA256 مع ملح عشوائي، وأدوار مدير النظام والمحاسب والعرض فقط.
- **دليل الحسابات:** عرض الحسابات وإضافة الحسابات الفرعية وتفعيلها أو إيقافها، مع حماية حسابات التحكم المستخدمة في الترحيل.
- **القيود اليومية:** قيود متعددة السطور، والتحقق من توازن المدين والدائن، وترحيل القيد وسجل تدقيق؛ لا يُسمح بحذف القيد المرحّل مباشرة.
- **العملاء والموردون:** بيانات الأطراف ووسائل الاتصال والرقم الضريبي، وربط الأرصدة والحركات بالحساب الفرعي.
- **الأصناف والمخزون:** رصيد افتتاحي، سجل حركات المخزون، تقييم المخزون، متوسط تكلفة المشتريات، ومنع البيع عند عدم كفاية الكمية.
- **فواتير البيع والشراء:** تفاصيل متعددة الأصناف، احتساب ضريبة القيمة المضافة، إنشاء القيود المحاسبية وتحديث المخزون داخل معاملة واحدة.
- **مردودات البيع والشراء:** ربط المردود بالفاتورة الأصلية، التحقق من الكميات القابلة للإرجاع، وعكس الأثر المحاسبي والمخزني والضريبي.
- **سندات القبض والصرف:** ترحيل أثر السند على الصندوق أو البنك وذمم الطرف.
- **التقارير:** ميزان المراجعة، الأستاذ العام، الأرباح والخسائر، الميزانية العمومية، ملخص ضريبة القيمة المضافة، سجلات المبيعات والمشتريات والمردودات، تقييم المخزون وحركته وتسوياته، أرصدة العملاء والموردين، سجل السندات، وسجل التدقيق.
- **الإخراج:** تصدير التقارير إلى CSV بترميز UTF-8، ومعاينة وطباعة التقارير والجداول، وإنشاء نسخة احتياطية متسقة من قاعدة البيانات.

## الهوية وتصميم الواجهة

الواجهة عربية من اليمين إلى اليسار، بتصميم مكتبي كلاسيكي مضغوط، شريط علوي وشريط تنقل، وألوان الهوية الكحلية والزرقاء والذهبية. يميَّز القسم الحالي في التنقل. تدعم معاينة الطباعة جداول عربية متعددة الصفحات، مع تفضيل ورق A4 وتقسيم الأعمدة العريضة إلى مجموعات عند الحاجة.

## تشغيل النسخة المنشورة

1. افتح [آخر عمليات البناء في GitHub Actions](https://github.com/a4032262287gmailcom/alsaqr-lanzimat-almuhasabat-10-10-2026/actions).
2. افتح أحدث تشغيل ناجح لسير العمل **Build AlSaqr Accounting Desktop**.
3. من قسم **Artifacts** نزّل `AlSaqr-Accounting-win-x64`.
4. فك الضغط إلى مجلد مستقل وشغّل `AlSaqr.Accounting.exe`.
5. في التشغيل الأول أنشئ اسم المستخدم وكلمة مرور المدير (10 أحرف على الأقل).

تُحفظ قاعدة البيانات الافتراضية تحت:

`%LOCALAPPDATA%\AlSaqrAccounting\accounting.db`

لا تتصل هذه القاعدة تلقائيًا بقاعدة بيانات SQL Server الخاصة بالنظام القديم. لا تستورد بيانات العملاء أو الفواتير تلقائيًا، ولا تتضمن بيانات معاملات اختبار في قاعدة الاستخدام.

## البناء المحلي على Windows

يتطلب المشروع Visual Studio 2022 أو .NET 8 SDK.

```powershell
dotnet restore AlSaqr.Accounting.csproj -r win-x64
dotnet build AlSaqr.Accounting.csproj -c Release -r win-x64 --no-restore
dotnet run --project tests/AlSaqr.Accounting.Smoke/AlSaqr.Accounting.Smoke.csproj -c Release -r win-x64
dotnet publish AlSaqr.Accounting.csproj -c Release -r win-x64 -p:SelfContained=true -o artifacts/publish
```

ملف المشروع يستبعد بعض نماذج Windows Forms القديمة التي تستهدف واجهة خدمة محاسبية سابقة؛ نقطة التشغيل الحالية تستخدم النماذج المتوافقة مع النواة المحاسبية الحالية.

## اختبارات التكامل وحدود الاعتماد

نجح البناء واختبار التكامل المحاسبي الآلي ونشر Windows x64 في آخر تشغيل متحقق منه على GitHub Actions. يغطي اختبار التكامل مسارات تسجيل الدخول، الفواتير والقيود والسندات والمخزون والمردودات والضريبة والتقارير وسجل التدقيق.

هذا لا يثبت المطابقة الكاملة لكل شاشات وتقارير النظام القديم. يحتوي جرد المصدر على مئات الشاشات المحتملة وآلاف مراجع الأحداث والصلاحيات؛ تتطلب كل وحدة قديمة مطابقة حقولها ومصادر بياناتها وإجراءاتها ونتيجة تشغيلها قبل إعلان اكتمالها. وحدات مثل العقود والإيجار والرواتب والمطاعم والنقل والصيانة والفوترة الإلكترونية والفروع تحتاج إلى تحليل وتنفيذ واختبار مستقل بحسب الجرد الفعلي.

قبل الاستخدام على بيانات فعلية، اختبر الأرصدة الافتتاحية والقيود والضريبة والمخزون على قاعدة اختبار، واحتفظ بنسخ احتياطية منتظمة، واحصل على مراجعة محاسبية وضريبية مناسبة. نجاح البناء وحده ليس اعتمادًا قانونيًا أو ضريبيًا.
